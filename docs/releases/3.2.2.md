# WarpTuner 3.2.2

Release preparation notes. This document does not assert that the release has been published.

## Changes

- Harden HTTPS registration transport with finite socket timeouts, disabled automatic redirects and caching, and unchanged default TLS validation.
- Share a cooperative 45-second registration budget across API variants and follow-up requests.
- Attempt to disconnect active registration HTTP work when its coroutine is cancelled or the budget expires.
- Disable automatic saved-tunnel fallback until exclusive tunnel ownership is implemented. Registration itself no longer starts or stops a tunnel; existing default routing may still pass through an already-active VPN.
- Encrypt both account and configuration before publishing the pair with one SharedPreferences editor apply. An encryption failure or cancellation detected before publication leaves the previous pair untouched.
- Add cancellation, deadline, connection lifecycle/race and isolated Android persistence tests.
- Set versionName to 3.2.2 and versionCode to 7.

## Verification and limitations

- The user chose to defer physical Android-device acceptance testing. It remains outstanding.
- Full registration POST/GET, retry and persistence-boundary integration coverage remains incomplete.
- The changes are registration hardening, not a confirmed fix for issue #20 or proof of first registration without an external VPN.
- Connection disconnect is best effort. DNS, platform I/O and cleanup may still block; there is no guaranteed 45-second wall-clock limit. Structured concurrency waits for its workers to finish.
- Publishing both preferences together is not a durable database transaction, does not isolate other config-writing paths, and cannot roll back cancellation after publication.
- Final CI, required CodeQL results, merge state, release signing and release artifacts must be verified separately before declaring publication complete.
